# @tskmgr/client

## Basic usage

The client sends unauthenticated requests by default.

```ts
import { ClientFactory } from '@tskmgr/client';

const client = ClientFactory.createNew('http://localhost:3333', 'runner-1');
```

## Custom request headers

Custom headers apply to every API request, including task polling and file uploads.

```ts
const client = ClientFactory.createNew(baseUrl, runnerId, {
  headers: { 'X-Build-ID': buildId },
});
```

## OIDC authentication

Use an async header provider to get an access token from your OIDC integration. Use HTTPS when sending credentials.

```ts
const client = ClientFactory.createNew('https://tasks.example.org', runnerId, {
  headers: async () => ({
    Authorization: `Bearer ${await getAccessToken()}`,
  }),
});
```

### Header provider behavior

- The client resolves the provider before every fetch attempt, including retries.
- Your provider can cache tokens, refresh them on demand, and share a pending refresh promise across parallel calls.
- If the provider fails, that attempt sends no HTTP request.

### HTTP behavior

- Header names are case-insensitive.
- JSON requests default to `Content-Type: application/json`.
- Multipart uploads use the `Content-Type` and boundary generated by `fetch`.
- Requests configured with custom headers reject redirects to prevent credentials from being sent to another endpoint.
